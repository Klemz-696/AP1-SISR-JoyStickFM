2. Chaîne de Diffusion & Sécurisation par Reverse-Proxy Audio Sécurité des Auditeurs
🛡️ 2.1. Masquage du Port 8000 via Apache

Dans un souci de sécurité et d'ergonomie, les auditeurs web ne se connectent jamais directement au port 8000 d'Icecast :

  • Directive ProxyPass : Apache intercepte les requêtes sur /radio-stream.mp3 et les relaie en interne vers http://10.100.0.50:8000/joystick-fm avec flushpackets=on.
  • Contournement CORS natif : Le navigateur télécharge le flux audio depuis la même origine (port 80), évitant tout blocage cross-origin sur mobile et Safari.
  • API d'état en direct : icecast-proxy.php interroge Icecast toutes les 5 secondes et renvoie le statut JSON (titre, artiste, auditeurs) au player frontend.
📜 2.2. Configuration Apache VirtualHost (/etc/apache2/sites-available/000-default.conf)
<VirtualHost *:80> DocumentRoot /var/www/html <Directory /var/www/html> Options -Indexes +FollowSymLinks AllowOverride All Require all granted </Directory> # Reverse-Proxy Audio transparent vers Icecast DMZ : ProxyPass "/radio-stream.mp3" \ "http://10.100.0.50:8000/joystick-fm" flushpackets=on disablereuse=on ProxyPassReverse "/radio-stream.mp3" \ "http://10.100.0.50:8000/joystick-fm" Header set Access-Control-Allow-Origin "*" </VirtualHost>
